# 不烧心 · 视频制作包

> 拍宣传视频用。含**两套分镜**（技术向 / 业务向）、逐字稿、屏幕文字、剪辑节奏、封面标题。
> 所有要投屏的文本都在 [video-assets.txt](video-assets.txt) 里，**不要手抄，直接从那里复制**。

---

## 零、拍摄前必做（3 分钟，别跳过）

```bash
cd <插件目录>
npm run demo                    # 重建演示产物
npm test                        # 应为 35/35 通过
node test/video-assets.mjs      # 重建拍摄素材包
```

**然后重启 DSH 并刷新页面。** 理由：

- 插件进程只在启动时加载一次模块。**不重启，演示会走旧代码**——生活类例子会落到错误领域、输出软件行话，录进视频里就废了。
- 客户端 bundle 也要刷新才会加载滑条。

**录屏设置建议**：

| 项 | 建议值 |
|---|---|
| 分辨率 | 1920×1080（终端字体 ≥ 16pt，手机上看也清楚） |
| 终端主题 | 深色（黑底），文字对比强，录屏压缩后更清晰 |
| 鼠标 | 录屏时开"显示点击位置"特效，否则观众不知道你在点哪 |
| 演示页 | `http://127.0.0.1:19387/dsh-bushaoxin/demo.html`（自带左右对比） |

### 旁白全文（可直接 TTS 或配音）

> 等一下。
>
> 这句话是对的。但它没用。
>
> 因为「不建议使用 `--force`」——它和我们每天看的几百条提示，长得一模一样。
>
> 不烧心想干的事只有一件：**它不改代码，不改模型，不提效率。它改的只是你听警告时的注意力。**
>
> 同一条建议，换一种说法：隔壁那家「一键装依赖」的店挂出招牌——「充值即送 `--force`，三秒解决，包过。」三分钟后，构建在 CI 上翻车。
>
> 技术信息一个字没少。少的是「你听完就忘」这件事。
>
> 它也不是复读一句台词。换个话题——异常它说「账要记」，时区它说「钟要对得上灶」，密钥它说「钥匙不进仓库」。同一个骨架，每个领域换一套行话。
>
> 辣度你说了算。点开滑条，四档：关、轻、中、重。拖一下就行。
>
> 但有一条是写死的：每篇末尾永远附一行真实技术结论。
>
> **段子可以让路，事实不行。**
>
> 不烧心。

### 旁白全文

> 三个月前，你换了这家供应商。
>
> 便宜三成，出货还快一倍。这笔账怎么算都划算。
>
> 只是当时没人说那句：**这批货，要留个样。**
>
> 不烧心做的就这一件事：**它不帮你省钱。它只让你在签字之前，多停半秒。**
>

> 它没有多讲一句道理。它只是把「半年后」那笔账，提前摆在你今天签字的时候。
>

>
> 但它有条规矩——每次的段子后面，必须跟一句真正该做的事。
>
> **它不会让你做错决定。它只会让你多想半秒。**

## 七、诚实交代（如果要露脸讲技术，把这段留着）

> 我一开始想做的是"事后改写助手的回复"。**做不到。**
>
> 消息是先写进会话、再发事件的；客户端跟着流式输出实时渲染。等你拿到全文，用户早看见了。没有钩子能改。
>
> 所以只能走**生成前注入**：把文风写进系统提示，让回复从一开始就是那个风格。
>
> 已知缺陷也说清楚：系统提示里那段文风正文是插件加载时定死的，滑条改了宿主状态、也改了本轮回复，但那段正文本次运行内不会跟着变。

**这段不要剪掉。** 视频里主动说边界，比被人问出来强十倍。
